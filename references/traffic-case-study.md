# Lessons extracted from a traffic-learning reference

This is a methodological case study, not bundled traffic source code or a claim to own/relicense the reference. Private paths, account identifiers and conversations are deliberately omitted.

## What transfers
1. Start with a learning goal, adjustable variables, measurable outputs and constraints.
2. Use a deterministic pure JavaScript fixed-step model before building the view.
3. Map actual model state to real Three.js geometry and persistent entity IDs.
4. Link object picking, camera focus, selection marker, path preview, details panel and entity list.
5. Test conservation, signal conflict constraints, geometric continuity, pause/reset and history isolation.
6. Compare plans from a deep-cloned checkpoint with control-independent arrival streams.
7. Perform real browser/GPU acceptance after unit/DOM/geometry tests.
8. Validate all delivered resources, including workers, from the served artifact.

A restrained matte low-poly environment, strong silhouettes, soft shadows, camera presets and sparse state accents made the model approachable. The transferable principle is visual legibility plus causal coupling, not a mandatory city aesthetic.

## Regressions that shaped this skill
- A timeline could show a late timestamp while geometry remained at the initial state: test actual object transforms and hold the frame across future render ticks.
- Replacing a model could also replace its audit container: separate promised application-session history from simulation lifetime.
- An entity-focus button could fall back to an unrelated entity type: require exact ID/type or explicit absence.
- A complex mode must not masquerade as a simpler model by merely hiding UI: remove the causal factors or call it a focused view of the same model.
- Particle weather must agree with simulation time and the physical parameters it represents.

## Evidence boundaries
Historical source records report 80 passing tests for a stable release and selected browser checks by another operator. A later working source reports 90 tests and new weather/mode changes; this is a different, actively changing artifact. These are reported evidence, not independent GPU acceptance by this package's author. Source and built release must not be conflated.

The traffic reference uses conservative single-vehicle intersection reservations, not realistic simultaneous nonconflicting throughput. It excludes several real traffic behaviors and is not field-calibrated or certified. The language-model and real-device connections are absent in the stable public demonstration. An explicit manual structured workflow is not proof of intelligent understanding.

Do not transfer these simplifications silently to another domain, publish reference source without a license review, or count several traffic modes as cross-domain validation.
